Quick Start

Démarrer l'intégralité de la stack PAD en quelques commandes.

Démarrage rapide — Full Stack Docker

La méthode recommandée pour lancer PAD est via Docker Compose, qui démarre automatiquement tous les services (MinIO, Redis, Backend, AI Worker).

  1. Cloner le dépôt
    git clone git@github.com:Bastientt/PAD.git
cd PAD
  2. Générer les clés JWT EdDSA
    Les clés doivent être présentes avant de démarrer le backend. 
    # Créer le dossier des clés
mkdir -p backend/key

# Générer la clé privée Ed25519
openssl genpkey -algorithm ED25519 -out backend/key/private_key.pem

# Extraire la clé publique
openssl pkey -in backend/key/private_key.pem -pubout -out backend/key/public_key.pem
  3. Lancer la stack complète
    docker compose up --build

    Le premier build peut prendre 3-5 minutes (compilation Rust + download des images Python/MinIO).

  4. Vérifier que les services sont actifs
    ServiceURL / PortCredentials
    Backend APIhttp://localhost:8080—
    MinIO Consolehttp://localhost:9001minioadmin / minioadmin
    MinIO S3 APIhttp://localhost:9000minioadmin / minioadmin
    Redislocalhost:6379—
  5. Tester le backend
    # Obtenir un token JWT
curl http://localhost:8080/Authentificate -c cookies.txt

# Initialiser une session (requiert le cookie)
curl http://localhost:8080/init-sesssion -b cookies.txt
ℹ️

MinIO : créer le bucket manuellement

Au premier démarrage, ouvrez http://localhost:9001, connectez-vous avec minioadmin/minioadmin, et créez un bucket nommé pad-bucket avec accès public en lecture.

Développement sans Docker

Backend Rust

cd backend/

# Variables d'environnement nécessaires
export REDIS_URL=redis://localhost:6379
export AWS_ACCESS_KEY_ID=minioadmin
export AWS_SECRET_ACCESS_KEY=minioadmin

# Compiler et lancer
cargo build --release
./target/release/mon_projet_ws

AI Worker Python

cd ia_worker/

# Installer les dépendances
pip install \
  opencv-python-headless==4.8.0.76 \
  numpy==1.24.3 \
  mediapipe==0.10.11 \
  protobuf==3.20.3 \
  redis \
  boto3 \
  absl-py attrs flatbuffers matplotlib

# Variables d'environnement
export REDIS_URL=redis://localhost:6379
export AWS_ACCESS_KEY_ID=minioadmin
export AWS_SECRET_ACCESS_KEY=minioadmin
export RATIO=0.70

python ai_worker.py

Application Android

cd Ring3_App/

# Compiler le projet
./gradlew assembleDebug

# Installer sur un device connecté ou émulateur
./gradlew installDebug
⚠️

URL du backend dans l'app Android

L'application pointe par défaut vers http://10.0.2.2:8080 (adresse host depuis l'émulateur Android). Pour un device physique, modifier l'URL dans MainActivity.kt pour pointer vers l'IP de votre machine.

Vérification end-to-end

Une fois tous les services démarrés, le flux complet est :

  1. L'app Android appelle GET /Authentificate → reçoit un cookie JWT
  2. L'app appelle GET /init-sesssion → reçoit une URL S3 pré-signée + un challenge
  3. L'utilisateur filme les mouvements demandés
  4. La vidéo est uploadée sur MinIO via l'URL pré-signée
  5. L'app envoie UploadDone|challenge via WebSocket
  6. Le backend publie le job sur Redis ia_jobs
  7. L'AI Worker analyse la vidéo et publie le résultat sur ia_results
  8. Le backend retransmet le résultat à l'app via WebSocket
