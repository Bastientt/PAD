Étape 1 — Prétraitement des frames

Chaque frame est prétraitée pour améliorer la robustesse de la détection dans des conditions d'éclairage variables.

# CLAHE — Contrast Limited Adaptive Histogram Equalization
clahe = cv2.createCLAHE(clipLimit=2.0, tileGridSize=(8,8))
l_channel = clahe.apply(l_channel)

# Filtre bilatéral — préserve les contours
processed = cv2.bilateralFilter(img, d=5, sigmaColor=75, sigmaSpace=75)

# Redimensionnement (ratio aspect préservé)
scale = RESIZE_WIDTH / w  # RESIZE_WIDTH = 640

Étape 3 — Calcul de la pose relative

Plutôt que des angles d'Euler absolus (sensibles à l'inclinaison de la tête au repos), PAD utilise des coordonnées relatives normalisées par la distance inter-oculaire.

# Milieu entre les deux yeux (repère de référence)
eye_mid_x = (left_eye.x + right_eye.x) / 2
eye_mid_y = (left_eye.y + right_eye.y) / 2

# Distance inter-oculaire (normalisation)
eye_distance = sqrt((right_eye.x - left_eye.x)**2 + (right_eye.y - left_eye.y)**2)

# Position relative du nez par rapport au milieu des yeux
rel_x = -(nose.x - eye_mid_x) / eye_distance  # + = droite, - = gauche
rel_y = -(nose.y - eye_mid_y) / eye_distance  # + = bas, - = haut
ℹ️

Pourquoi normaliser par la distance inter-oculaire ?

La distance entre les yeux varie selon la distance de l'utilisateur à la caméra. En divisant par cette distance, les coordonnées deviennent invariantes à la distance et représentent de vrais angles relatifs.

Étape 4 — Lissage du signal

Une moyenne glissante sur les 4 dernières frames réduit le bruit provenant des micro-vibrations de la caméra et de la latence du détecteur.

SMOOTHING_FRAMES = 4

# Buffer circulaire des dernières positions
x_history = deque(maxlen=SMOOTHING_FRAMES)
y_history = deque(maxlen=SMOOTHING_FRAMES)

x_history.append(rel_x)
y_history.append(rel_y)

smooth_x = mean(x_history)
smooth_y = mean(y_history)

Étape 5 — Machine à états avec hysteresis

L'hysteresis est essentielle pour éviter les oscillations rapides autour du seuil. Le système utilise des seuils asymétriques : un seuil de déclenchement haut et une zone centrale plus petite pour sortir de l'état.

Seuils de détection

ParamètreValeurRôle
X_THRESHOLD0.45Déclenchement mouvement horizontal (GAUCHE/DROITE)
Y_DOWN0.32Déclenchement mouvement vers le bas
Y_UP-0.08Déclenchement mouvement vers le haut (asymétrique)
X_CENTER_ZONE0.28Zone morte horizontale (retour au centre)
Y_CENTER_DOWN0.18Zone morte basse
Y_CENTER_UP-0.02Zone morte haute
CONFIRM_FRAMES5Frames consécutives pour confirmer un état
⚠️

Asymétrie HAUT/BAS

Y_UP = -0.08 est intentionnellement plus petit que Y_DOWN = 0.32 car lever la tête cache progressivement le nez derrière les plans du visage, ce qui réduit la sensibilité. Le seuil abaissé compense cette perte de signal.

Logique de transition

class State:
    CENTER = "CENTER"
    HAUT   = "HAUT"
    BAS    = "BAS"
    GAUCHE = "GAUCHE"
    DROITE = "DROITE"

def next_state(x, y, current_state):
    if current_state == State.CENTER:
        # Transitions depuis CENTER
        if   x >  X_THRESHOLD:  return State.DROITE
        elif x < -X_THRESHOLD:  return State.GAUCHE
        elif y >  Y_DOWN:        return State.BAS
        elif y <  Y_UP:          return State.HAUT
        return State.CENTER

    else:
        # Retour au centre uniquement depuis la zone morte
        in_center = (
            -X_CENTER_ZONE <= x <= X_CENTER_ZONE and
            Y_CENTER_UP    <= y <= Y_CENTER_DOWN
        )
        return State.CENTER if in_center else current_state

Confirmation par frames consécutives

# Un changement d'état n'est enregistré que si stable sur N frames
if candidate_state == prev_candidate:
    confirm_counter += 1
else:
    confirm_counter = 0
    prev_candidate = candidate_state

if confirm_counter >= CONFIRM_FRAMES:
    if candidate_state != current_state:
        record_transition(candidate_state)
    current_state = candidate_state
    confirm_counter = 0

Étape 6 — Scoring du challenge

Une fois la vidéo entièrement analysée, la liste des mouvements détectés est comparée séquentiellement au challenge.

def score_challenge(detected_moves, challenge):
    """
    Parcourt le challenge dans l'ordre.
    Pour chaque étape du challenge, cherche le prochain mouvement
    correspondant dans la liste détectée (ordre préservé).
    """
    matching = 0
    det_idx = 0

    for step in challenge:
        while det_idx < len(detected_moves):
            if detected_moves[det_idx].direction == step:
                matching += 1
                det_idx += 1
                break
            det_idx += 1

    score = matching / len(challenge)
    return score >= RATIO   # RATIO = 0.60 par défaut
✅

Tolérance configurable

Le paramètre RATIO (défaut 0.60, soit 60%) peut être ajusté via la variable d'environnement RATIO dans docker-compose.yaml. Une valeur plus haute (ex: 0.85) est plus stricte mais peut rejeter des utilisateurs légitimes.

Gestion de la perte de visage

Si MediaPipe ne détecte plus de visage pendant plusieurs frames, le système entre en mode "grace period" avant de réinitialiser l'état.

FACE_GRACE_FRAMES = 20   # ~0.67s à 30fps

if no_face_detected:
    grace_counter += 1
    if grace_counter > FACE_GRACE_FRAMES:
        # Réinitialiser la machine à états
        current_state = State.CENTER
        confirm_counter = 0
        grace_counter = 0
else:
    grace_counter = 0
